# 메뉴·대화상자·버튼 데스크톱 리디자인 설계

작성일: 2026-10-27
브랜치: `feat/design-ui`
상태: 사용자 승인 대기

사용자가 정한 것: 두 OS에서 똑같이 보인다 / 메뉴는 시안 A(유리) / 대화상자는 시안 1(경고창 + 하단 띠) / 대화상자에 아이콘 없음 / 하단 버튼 띠는 촘촘하게 / 버튼은 시안 C(중간) / 메뉴·대화상자 전부 다시 디자인 / 기본 버튼 전체에 적용 / 큰 창도 하단 띠 구조.

시안(브라우저로 비교한 것)은 `.superpowers/brainstorm/33605-1793097347/content/`에 있다: `menu-style.html`(A), `dialog-style-v3.html`(1, 촘촘한 띠), `button-style.html`(C).

## 1. 의도와 이유

메뉴(우클릭·상단 메뉴·드롭다운)와 대화상자가 shadcn 기본 스타일 그대로라 **웹 화면처럼** 보인다. 사용자 표현으로 "흰색 모달류가 너무 빈약해 보인다".
앱은 이미 데스크톱 밀도(13px 본문, Segoe UI/SF Pro, OS 셸 아이콘)로 맞춰 왔으니, 떠오르는 화면 요소도 **잘 만든 데스크톱 프로그램**처럼 보이게 한다.

## 2. 목표 / 비목표 / 반목표

**목표**
- 메뉴 4종(우클릭, 상단 메뉴 막대, 드롭다운, 하위 메뉴)이 같은 유리 스타일
- 대화상자 8개가 같은 구조(본문 + 하단 회색 띠)와 같은 버튼
- 기본 버튼(`Button`의 `default`·`outline`·`destructive`)이 데스크톱 버튼처럼
- 윈도우·맥에서 같은 모습

**비목표**
- OS별로 다르게 보이게 하기(맥은 맥 메뉴, 윈도우는 윈도우 메뉴) — 사용자가 거절
- 다크 모드 켜는 버튼 만들기(토큰만 맞춰 둔다)
- 파일 목록·사이드바·타이틀바 자체의 리디자인
- 대화상자 내용(문구, 필드 구성, 동작) 변경

**반목표 (이러면 실패)**
- 웹 느낌이 남는 것: 확대되며 튀어나오는 애니메이션, 투명도로만 어두워지는 hover, 평면 단색 버튼
- 과한 것: 그라데이션·반사광이 눈에 띄는 버튼(사용자가 "오바"라고 한 1차 시안)
- 대화상자에 아이콘 타일 같은 장식("OS에 그런 거 없다")
- 윈도우 화면이 지금보다 나빠지는 것(이 작업은 두 OS 공통이므로 윈도우에서도 확인해야 함)

## 3. 제약

- `docs/DESIGN.md` 규칙: 색·그림자는 `src/index.css` 토큰에만 정의하고, `src/features`에서는 토큰 클래스만 쓴다(`npm run lint`가 잡음). 새 값은 토큰으로 추가한다.
- 컴포넌트 수정은 `src/components/ui/`에서 한다. 기능 코드는 가능하면 건드리지 않는다.
- Base UI(`@base-ui/react`) 기반 shadcn 컴포넌트. 파일마다 줄바꿈이 다르다(CRLF/LF 섞임) — 수정 시 원래 줄바꿈 유지.
- 반투명 흐림(`backdrop-filter`)은 Tauri WebView(맥 WKWebView, 윈도우 WebView2) 모두 지원.

## 4. 결정된 것

### 4.1 메뉴 (시안 A · 유리)

적용: `context-menu.tsx`, `dropdown-menu.tsx`, `menubar.tsx`의 팝업·항목·구분선·하위 메뉴.

| 부분 | 값 |
| --- | --- |
| 바탕 | 반투명 `rgb(246 246 246 / .72)` + `backdrop-filter: blur(24px) saturate(180%)` |
| 모서리 / 안쪽 여백 | 10px / 5px |
| 테두리·그림자 | `0 0 0 .5px rgb(0 0 0/.18)`, `inset 0 0 0 .5px rgb(255 255 255/.7)`, `0 12px 32px rgb(0 0 0/.18)`, `0 2px 8px rgb(0 0 0/.08)` (기존 `ring-1`은 없앤다) |
| 항목 | 높이 24px, 왼 8px·오 10px, 모서리 5px, 아이콘과 글자 사이 8px, 13px |
| 강조(마우스 올림·키보드 이동) | `primary` 바탕 + 흰 글자. 아이콘·단축키·화살표도 흰색 85% |
| 위험 항목(삭제) 강조 | `destructive` 바탕 + 흰 글자. 평소엔 빨간 글자 그대로 |
| 구분선 | 1px `rgb(0 0 0/.1)`, 위아래 5px, 좌우 10px 안쪽으로 |
| 단축키·하위 메뉴 화살표 | 오른쪽, 12px, 회색(`muted-foreground`). 맥 자간 보정(`mac:tracking-normal`) 유지 |
| 체크·라디오 | 오른쪽 끝(이미 그렇게 바꿈) |
| 아이콘 칸 | 아이콘이 있는 메뉴에서는 아이콘 없는 항목도 글자 시작선을 맞춘다 |
| 열기/닫기 | 확대·미끄러짐 없음. 열 때 즉시(또는 80ms 이하 페이드), 닫을 때 100ms 페이드 |

### 4.2 대화상자 (시안 1 · 경고창 + 하단 띠, 아이콘 없음)

적용: `dialog.tsx`를 바꿔 8개 전부에 반영. 삭제 확인, 덮어쓰기 확인, 링크 삭제 확인, 공유 링크, 설정, 휴지통, 키보드 단축키(상단 메뉴), Drive 정보(상단 메뉴). 미리보기는 4.4 참고.

| 부분 | 값 |
| --- | --- |
| 상자 | 흰 바탕(`card`), 모서리 12px, 그림자 `0 0 0 .5px rgb(0 0 0/.2)`, `0 24px 60px rgb(0 0 0/.25)`, `0 4px 12px rgb(0 0 0/.08)`. `ring-1` 없앰 |
| 뒤 배경 | 검정 18%로 어둡게. 흐림 없음 |
| 본문 | 안쪽 여백 18px(아래 16px) |
| 제목 | 14px, 굵게(600) |
| 설명 | 13px, 회색, 줄 간격 1.45 |
| 하단 띠 | 바탕 `#f5f5f5`, 위 테두리 `#e6e6e6`, 위아래 7px·좌우 10px, 버튼 사이 6px, 오른쪽 정렬. 좁은 화면에서도 세로로 쌓지 않는다 |
| 아이콘 | 넣지 않는다 |
| 열기/닫기 | 확대 없음. 짧은 페이드만 |

### 4.3 버튼 (시안 C · 중간)

적용: `button.tsx`의 `default`, `outline`, `destructive`. `ghost`·`link`·`secondary`와 아이콘 크기(`icon*`)는 지금 모양 유지(툴바 아이콘 버튼 등).

| 변형 | 바탕 / 글자 | 테두리 (위·옆 / 아래) | 그림자 |
| --- | --- | --- | --- |
| `default`(확인, 파랑) | `primary` / 흰색 | `#0a5bb8` / `#074a96` | `0 1px 1px rgb(0 0 0/.1)` |
| `outline`(취소, 흰색) | 흰색 / 기본 글자색 | `#d6d6d6` / `#bdbdbd` | `0 1px 1px rgb(0 0 0/.05)` |
| `destructive`(삭제, 빨강) | `destructive` / 흰색 | `#b52617` / `#921e12` | `0 1px 1px rgb(0 0 0/.1)` |

- 기본 크기: 높이 26px, 좌우 12~13px, 모서리 6px, 글자 13px 보통 굵기(400)
- 그라데이션·안쪽 반사광 없음
- `destructive`는 지금(옅은 빨강 바탕 + 빨간 글자)에서 **진한 빨강 + 흰 글자**로 바뀐다. 사용처는 대화상자 두 곳(삭제 확인, 링크 삭제 확인)뿐

### 4.4 미리보기

`PreviewModal.tsx`는 자체 레이아웃(화면 88%, 패딩 0, 자체 헤더)을 쓴다. 상자 모서리·그림자·뒤 배경만 4.2를 따르고 내부 구조는 바꾸지 않는다.

## 5. 내가 정한 것 (사용자 확인 전, 검토해 주세요)

- **다크 모드 토큰**: 메뉴 바탕 `rgb(40 40 42/.72)`, 구분선 `rgb(255 255 255/.1)`, 하단 띠·버튼 테두리도 `.dark`에 맞는 값을 정의만 해 둔다.
- **닫기(✕) 버튼**: 하단 띠에 버튼이 있는 대화상자에서는 없앤다(시안 1에 없음, Esc로도 닫힘). 하단 띠가 없는 대화상자(키보드 단축키, Drive 정보)는 오른쪽 위 ✕를 유지한다.
- **큰 창(설정·휴지통)**: 같은 본문 + 하단 띠 구조. 내용이 길면 본문만 스크롤되고 하단 띠는 고정. 창 너비는 지금 값(`max-w-md`, `max-w-xl`) 유지.
- **버튼 hover/누름**: 투명도 대신 같은 색의 조금 밝은/진한 단색(토큰으로 정의). 눌렀을 때 1px 내려가는 효과는 없앤다(웹 느낌). 키보드 초점 표시는 2px `primary` 40% 링.
- **버튼 크기 체계**: 기본 26px 기준으로 `sm` 24px, `lg` 28px로 맞춘다(지금은 `sm`이 28px로 기본보다 큼). `xs`·아이콘 크기는 유지.
- **입력칸**: 대화상자 안에서 버튼과 어울리게 높이 26px, 모서리 6px, 초점 링 2px로 맞춘다.
- **툴팁**: 지금처럼 어두운 바탕을 유지하되, 화살표를 없애고 모서리 5px·작은 여백, 확대 애니메이션 없이 페이드만. (OS 툴팁에는 화살표가 없다)
- **오른쪽 아래 알림 패널**(업데이트 알림, 다운로드·업로드 진행): 대화상자와 같은 그림자·모서리 언어(12px, 같은 그림자)로 맞추고, 아래에서 미끄러져 올라오는 움직임은 짧은 페이드로 바꾼다.

- **메뉴 막대의 메뉴 이름**(파일·편집·보기… 버튼 자체): 그대로 둔다. 바뀌는 건 펼쳐진 메뉴뿐.
- **대화상자 밖의 버튼도 바뀐다**: "기본 버튼 전체 적용"에 따라 로그인 버튼, 아래쪽 선택 막대(`FileSelectionBar`)의 버튼 등도 같은 모양이 된다. 로그인 버튼처럼 클래스로 크기를 직접 정한 곳은 그 크기를 유지한다.
- **체크박스·진행 막대**: 이번 범위에서 손대지 않는다(대화상자 안에 있어도 그대로).

## 6. 만드는 사람 재량

- 아이콘 칸 맞추기 방법(항목의 `inset` 속성 활용, 또는 메뉴 단위 처리)
- 정확한 hover 색, 애니메이션 시간(위 범위 안에서)
- 토큰 이름
