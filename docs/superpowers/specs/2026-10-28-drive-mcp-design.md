# Drive MCP: Claude에서 드라이브로 올리고 받기

## 왜 만드나

요즘 동료들이 Claude Code와 Claude 데스크톱 앱으로 문서 작업을 많이 한다. 지금은 문서를 다 쓴 뒤 Drive 앱을 열어 직접 끌어다 올려야 한다. 이 단계를 대화 안에서 끝내려는 것이다.

핵심 장면은 다음과 같다.

> (Claude가 문서 작성을 끝낸 뒤)
> Claude: "드라이브에도 올릴까요? `내 라이브러리/피드백/2026-10/` 폴더를 만들어서 올리겠습니다."
> 사용자: "응"
> → 업로드. Drive 앱의 업로드 패널에도 표시된다.

받기도 한다. "드라이브에 있는 피드백 수집계획서 받아줘"라고 하면 Claude가 이름으로 찾아서 받는다.

Figma Desktop MCP처럼 **Drive 앱 안에 MCP를 넣는다**. 앱에 로그인돼 있으면 따로 인증할 필요가 없고, 업로드·다운로드는 앱의 기존 큐와 진행 패널을 그대로 쓴다.

## 목표

- Claude Code와 Claude 데스크톱 앱(채팅) **둘 다**에서 동작한다.
- 문서 작업이 끝나면 Claude가 먼저 "올릴까요?"라고 묻고, **폴더 위치를 제안**한다(사용자 본인 드라이브).
- 로컬 파일 올리기, 채팅에서 쓴 내용을 파일로 올리기.
- 이름으로 드라이브 파일을 찾아 받기.
- 동료 PC에 Node 같은 추가 설치가 필요 없다.

## 하지 않는 것

- 공유 링크 만들기: 올리고 저장해 두면 끝이라고 사용자가 말했다.
- 삭제·이름 변경·이동: Claude 실수로 데이터가 사라질 수 있는 동작은 넣지 않는다.
- 앱에서 "지금 보고 있는 폴더·선택한 파일"을 넘기는 도구: 업로드 위치를 Claude가 제안하는 흐름이라 우선순위가 낮다. 필요해지면 추가한다.
- 원격(클라우드) MCP, Claude 설정 파일 자동 등록.
- 채팅 작업 공간의 파일을 직접 올리기(base64 등): 클라우드 작업 공간은 내부망 Seafile에 닿지 않고, 내용을 토큰으로 넘기기엔 너무 크다. 사용자가 먼저 다운로드하게 안내하는 것으로 대신한다.

## 이렇게 되면 실패다

- 사용자 확인 없이 올라간다.
- 같은 이름 파일을 묻지 않고 덮어쓴다(서버 업로드는 `replace=1`이라 그냥 두면 덮어써진다).
- 동료가 Node나 다른 프로그램을 따로 깔아야 한다.
- MCP를 쓰지 않는 사람의 앱 동작이 달라진다.

## 구조

```
Claude Code / Claude 데스크톱 앱
   │ stdio (MCP JSON-RPC, 한 줄에 메시지 하나)
   ▼
Drive --mcp   ← 같은 실행 파일, 창 없이 중계만 하는 모드
   │ TCP 127.0.0.1 (줄 단위 JSON 그대로 전달 + 첫 줄에 토큰)
   ▼
실행 중인 Drive 앱 (Rust)
   │ emit("mcp-request", {conn, line}) / invoke("mcp_respond", {conn, line})
   ▼
WebView JS: MCP 프로토콜 처리 + 도구 실행 (기존 StorageProvider·UploadQueue·downloads 사용)
```

### 왜 stdio 하나로 통일하나

확인한 결과는 이렇다(2026-10-28 기준).
- Claude Code는 로컬 HTTP MCP(`--transport http`)를 붙일 수 있다.
- Claude 데스크톱 앱의 `claude_desktop_config.json`은 stdio 서버만 받는다는 보고가 대부분이다. 보통 `mcp-remote`(Node 필요)로 우회한다.

그래서 **Drive 실행 파일 자체가 stdio 중계 프로그램** 역할을 하고, 두 클라이언트 모두 같은 방식으로 등록한다. 앱과의 통신은 HTTP가 아닌 TCP 줄 단위 프로토콜을 쓴다. 이러면 브라우저가 접근할 수 없어 DNS rebinding 같은 문제가 생기지 않는다.

### 1. 중계 모드 (`Drive --mcp`)

- `main.rs`에서 `--mcp` 인자를 보면 Tauri를 띄우지 않고 중계만 한다.
- 앱 설정 폴더의 `mcp.json`(`{port, token}`)을 읽어 TCP로 접속하고, 첫 줄에 토큰을 보낸 뒤 stdin↔소켓을 줄 단위로 그대로 전달한다.
- **앱이 꺼져 있으면**(파일이 없거나 접속 실패) `Drive --autostart`로 앱을 창 없이 띄운다. 그 뒤 일정 시간(예: 15초) 접속을 재시도한다. 끝내 실패하면 표준 에러에 사유를 남기고 종료한다.
- **쓰는 도중 연결이 끊기면**(사용자가 트레이에서 종료한 경우 등) 중계는 종료하지 않는다. 다음 메시지가 오면 위와 같이 앱을 띄우고 다시 접속한다. 끊긴 순간 처리 중이던 요청에는 JSON-RPC 오류로 답한다.
- **업데이트**: 설치기가 `Drive.exe` 프로세스를 끝내면 중계도 함께 끝나서 Claude 쪽 연결이 끊긴다. 이것은 받아들인다. 업데이트 뒤 Claude Code는 `/mcp`로 다시 연결하고, 데스크톱 앱은 다시 시작하면 된다.

### 단일 실행

`tauri-plugin-single-instance`를 넣어 앱이 하나만 뜨게 한다. 사용자가 승인했다. 두 번째 실행은 기존 창을 앞으로 띄우고 끝난다. 단, `--autostart`로 두 번째 실행이 들어오면 창을 띄우지 않는다. 이 변경으로 MCP를 쓰지 않는 사람도 아이콘을 다시 누르면 새 창 대신 기존 창이 나온다. 이는 의도된 변경이다. `--mcp` 중계 모드는 Tauri를 띄우기 전에 갈라지므로 단일 실행 검사에 걸리지 않는다. 동시에 시작한 중계 둘이 각각 앱을 띄워도, 단일 실행 덕분에 앱은 하나만 남는다.
- **확인 필요(가장 먼저 검증)**: Windows 릴리스 빌드는 `windows_subsystem = "windows"`다. 이 상태에서 부모 프로세스가 넘긴 파이프로 stdin/stdout이 동작하는지 먼저 확인한다. 안 되면 콘솔 서브시스템의 작은 별도 실행 파일(`drive-mcp.exe`)을 사이드카로 함께 배포한다.

### 2. 앱 쪽 리스너 (Rust)

- 앱이 시작되면 `127.0.0.1:0`(빈 포트)에 바인드하고, 무작위 토큰과 함께 `mcp.json`에 기록한다. 종료 시 지우는 건 선택 사항이다. 중계 모드가 접속 실패로 판단하면 된다.
- 연결마다 id를 매긴다. 첫 줄의 토큰이 틀리면 끊는다. 이후 받는 줄은 `mcp-request {conn, line}` 이벤트로 WebView에 넘긴다.
- `mcp_respond {conn, line}` 커맨드로 받은 줄을 해당 소켓에 쓴다.
- 여러 연결(Claude Code와 데스크톱 앱 동시 사용)을 받을 수 있어야 한다.
- WebView가 아직 준비되지 않았을 때(자동 실행 직후) 들어온 줄은, JS가 준비 신호를 보낼 때까지 Rust가 버퍼에 들고 있는다.

### 3. MCP 처리 (JS)

- 로그인된 화면 안(`UploadQueueRoot` 아래)에 화면 없는 컴포넌트 하나를 두고, `mcp-request`를 듣는다. 이 위치면 storage·업로드 큐·검색 인덱스 훅을 그대로 쓸 수 있다.
- **로그인 전에도 응답해야 한다.** `initialize`·`tools/list`는 항상 답하고, `tools/call`만 "Drive 앱에서 로그인해 주세요" 오류를 돌려준다. 그래서 리스너 컴포넌트는 로그인 여부와 상관없이 앱 최상단에 두고, 도구 실행에 필요한 것만 로그인 상태에서 연결하는 구조가 필요하다. 어떻게 나눌지는 빌더가 정한다.
- 프로토콜은 `initialize`, `notifications/initialized`, `ping`, `tools/list`, `tools/call`만 있으면 된다. 직접 짤지 `@modelcontextprotocol/sdk`의 `Server`에 커스텀 Transport를 붙일지는 빌더가 정한다.

### 서버 안내문 (`initialize`의 `instructions`)

Claude의 행동은 이 안내문과 도구 설명으로 유도한다. 담을 내용은 다음과 같다.
- 사용자가 문서 작성·수정을 끝내면 "드라이브에도 올릴까요?"라고 먼저 물어볼 것.
- 올리기 전에 `list_libraries`와 `list_dir`로 사용자 본인 저장소(섹션 "내 저장소")의 기존 구조를 보고, 거기에 맞는 폴더 경로를 제안할 것. 새 폴더가 필요하면 "이 폴더를 만들어서 올릴까요?"라고 말할 것.
- **사용자 확인 없이 `upload_*`를 부르지 말 것.**
- 같은 이름 충돌 응답을 받으면 덮어쓸지 사용자에게 묻고, 동의할 때만 `overwrite: true`로 다시 부를 것.
- 받기는 Claude Code라면 현재 작업 폴더의 절대 경로를 `local_dir`로 넘기고, 경로를 모르면(채팅) 생략할 것.
- 올릴 파일이 사용자 PC가 아닌 Claude 작업 공간(채팅에서 만든 docx·pdf 등)에 있으면, 먼저 "파일의 다운로드 버튼을 눌러 받아 주세요"라고 요청할 것. 사용자가 받았다고 하면 `recent_downloads`로 그 파일을 찾아 `upload_file`로 올릴 것. 텍스트 문서는 `upload_text`로 바로 올려도 된다.

이 안내는 Claude를 유도할 뿐 강제하지 않는다. 시스템이 확인을 강제하지 않는 것은 의도된 결정이다. Claude Code는 기본 설정에서 도구를 실행할 때마다 허락을 받고, Seafile은 파일 이전 버전을 남겨 덮어쓴 파일을 되살릴 수 있기 때문이다.

## 도구 (1차)

모든 경로는 저장소 안 경로로 `/`로 시작한다. `library`는 저장소 id다.

| 도구 | 입력 | 동작 |
|---|---|---|
| `list_libraries` | 없음 | id, 이름, 섹션, 읽기 전용 여부. 암호화 저장소는 표시만 하고 쓰기·받기 대상에서 뺀다 |
| `list_dir` | `library`, `path` | 이름, 종류, 크기, 수정 시각 |
| `search` | `query` | 전 저장소에서 이름으로 찾기. 기존 `useSearchIndex`의 캐시와 `searchEntries`를 쓴다. 결과에 저장소 이름과 경로 포함 |
| `upload_file` | `local_paths[]`, `library`, `dir`, `overwrite?` | 로컬 파일을 올린다 |
| `upload_text` | `name`, `content`, `library`, `dir`, `overwrite?` | 내용을 UTF-8 파일로 만들어 올린다(채팅용) |
| `download` | `library`, `paths[]`, `local_dir?` | 받아서 저장한 로컬 절대 경로들을 돌려준다 |
| `recent_downloads` | `limit?` | 다운로드 폴더(설정값, 없으면 OS 다운로드 폴더)의 최근 파일. 이름, 절대 경로, 크기, 수정 시각을 수정 시각 역순으로(기본 10개). 하위 폴더는 보지 않는다 |

### 올리기 세부

- **없는 폴더**: 별도 `mkdir` 도구 없이 올리기가 폴더를 만든다. Seafile 업로드의 `relative_path`가 중간 폴더를 만들어 주므로, 이미 있는 가장 가까운 상위 폴더를 `targetDir`로, 나머지를 `relativePath`로 넘긴다. 폴더 드롭 업로드가 이미 이 방식을 쓴다(`SeafileProvider.ts`의 `relative_path`).
- **충돌**: 올리기 전에 대상 폴더를 `listDir`로 확인한다. 같은 이름이 있고 `overwrite`가 참이 아니면, 아무것도 올리지 않고 충돌 목록을 담아 응답한다. 여러 파일 중 일부만 충돌해도 전부 멈춘다. 그래야 Claude가 한 번에 묻는다.
- **로컬 파일 읽기**: Rust 커맨드로 경로의 바이트를 읽어 JS에서 `File`로 만든다. 그다음 기존 `UploadQueue.add`에 넣어 업로드 패널에 뜨게 한다. 메모리에 통째로 올리므로 크기 상한을 둔다(예: 200MB, 넘으면 "앱에서 직접 올려 주세요" 오류). 문서 용도라 충분하다.
- **완료 대기**: 도구 응답은 해당 항목들이 끝날 때까지(완료·실패) 기다린 뒤 결과를 돌려준다. 큐에서 항목별 상태를 구독해 기다리는 방법이 필요하다.
- 읽기 전용 저장소에는 올리지 않는다.

### 받기 세부

- 저장 위치: `local_dir`가 있으면 그 폴더, 없으면 설정의 다운로드 폴더, 그것도 없으면 OS 다운로드 폴더. **대화상자는 띄우지 않는다.**
- 기존 `free_path`로 같은 이름을 피한다. 로컬 파일은 절대 덮어쓰지 않는다.
- 기존 `downloads` 큐에 넣어 다운로드 패널에 뜨게 하고, 끝날 때까지 기다린 뒤 저장 경로를 돌려준다.
- 폴더 받기는 1차에서 뺀다(파일만). 폴더를 지정하면 "파일만 받을 수 있습니다" 오류.

## 연결 방법 (설정 화면)

설정 대화상자에 "Claude 연결" 항목을 두고 두 가지를 복사 버튼과 함께 보여준다. 실행 파일 경로는 Rust에서 현재 실행 경로를 받아 채운다.

- Claude Code: `claude mcp add drive -- "<실행 파일 경로>" --mcp`
- Claude 데스크톱 앱: `claude_desktop_config.json`에 넣을 JSON 조각과, 그 파일을 여는 버튼
  ```json
  { "mcpServers": { "drive": { "command": "<실행 파일 경로>", "args": ["--mcp"] } } }
  ```
- macOS 실행 파일 경로는 `/Applications/Drive.app/Contents/MacOS/Drive` 형태다.

켜고 끄는 토글은 두지 않는다. Claude에 등록하는 행위 자체가 사용 의사 표시이고, 등록하지 않으면 리스너는 아무 일도 하지 않는다.

## 자원 사용

- 중계 프로세스는 WebView·Tauri를 띄우지 않는 입출력 루프라서 메모리는 수 MB 수준으로 예상된다(구현 후 측정). 대기 중 CPU는 0이다. Claude 세션마다 하나씩 뜬다.
- 중계로는 짧은 JSON만 오가고, 파일 데이터는 Drive 앱이 Seafile과 직접 주고받는다.

## 보안

- 리스너는 `127.0.0.1`에만 바인드한다.
- 토큰은 사용자 설정 폴더의 `mcp.json`에 있다. 같은 PC의 다른 OS 사용자는 접근할 수 없다. 같은 사용자의 다른 프로세스는 접근할 수 있지만, 그런 프로세스는 이미 WebView의 로그인 토큰도 읽을 수 있으므로 위험 수준이 달라지지 않는다.
- 삭제·이동 도구가 없다. 덮어쓰기는 명시적인 `overwrite: true`일 때만 한다.
- 도구가 Seafile 토큰을 응답에 담지 않는다. 로그에는 기존 `errorLog`의 마스킹을 거친다.

## 검증

- JS: 도구 처리기를 `MockProvider`로 단위 테스트한다(충돌 시 아무것도 안 올림, 폴더 경로 분해, 검색 결과 형태, 로그인 전 오류).
- JSON-RPC 처리: `initialize` → `tools/list` → `tools/call` 왕복 테스트 하나.
- 수동 확인: Windows·macOS 각각 Claude Code와 Claude 데스크톱 앱에서
  1. 앱이 꺼진 상태에서 도구 호출 → 앱이 트레이로 뜨고 응답한다
  2. 문서 작성 후 "올릴까요?" 제안 → 새 폴더에 올라가고 업로드 패널에 뜬다
  3. 같은 이름 → 덮어쓸지 묻는다
  4. "○○ 받아줘" → 작업 폴더(Code) 또는 다운로드 폴더(채팅)에 저장된다
  5. 채팅에서 만든 docx를 "올려줘" → 먼저 받아 달라고 안내한다 → 받은 뒤 다운로드 폴더에서 찾아 올린다
  6. 앱이 실행 중일 때 아이콘을 다시 누름 → 기존 창이 나온다
