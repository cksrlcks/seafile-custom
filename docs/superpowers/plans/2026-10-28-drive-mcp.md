# Drive MCP 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Claude Code와 Claude 데스크톱 앱에서 Drive 앱을 통해 드라이브로 파일을 올리고 받는다.

**Architecture:** `Drive --mcp`가 stdio↔TCP 중계를 맡는다. 실행 중인 앱의 Rust `Hub`가 TCP 줄을 WebView로 넘기고, WebView JS가 MCP JSON-RPC를 직접 처리한다. 도구는 기존 `StorageProvider`·`UploadQueue`·`downloads` 큐로 실행한다.

**Tech Stack:** Tauri 2, Rust std(`TcpListener`, 스레드), `serde_json`, `tauri-plugin-single-instance`(신규), React 19, TypeScript, vitest

**Spec:** `docs/superpowers/specs/2026-10-28-drive-mcp-design.md`

## Global Constraints

- MCP SDK는 쓰지 않는다. JSON-RPC는 직접 처리한다(`initialize`, `notifications/initialized`, `ping`, `tools/list`, `tools/call`만).
- TCP는 `127.0.0.1`에만 바인드하고, 포트는 0(빈 포트)을 쓴다. 첫 줄 토큰이 틀리면 연결을 끊는다.
- `mcp.json` 위치는 앱과 중계가 같은 함수로 계산한다. Windows는 `%APPDATA%\com.chang.seadrive\mcp.json`, macOS는 `~/Library/Application Support/com.chang.seadrive/mcp.json`.
- 중계 자동 실행 인자는 `--autostart`, 대기 시간은 15초, 재시도 간격은 300ms.
- 로컬 파일 읽기 상한은 200MB. 넘으면 "200MB가 넘는 파일은 Drive 앱에서 직접 올려 주세요" 오류.
- 삭제·이동·이름 변경·공유 링크 도구는 만들지 않는다.
- 덮어쓰기는 `overwrite: true`일 때만 한다. 충돌이 하나라도 있으면 아무것도 올리지 않는다.
- 로컬 파일은 덮어쓰지 않는다. 받을 때는 `free_path`를 쓴다.
- 받기와 MCP 업로드는 대화상자를 띄우지 않는다.
- 도구 응답·오류 문구는 한국어로 쓴다. Seafile 토큰은 응답에 담지 않는다.
- 이 저장소의 주석 밀도와 한국어 주석 관례를 따르고, `npm run lint`를 통과해야 한다.

### Task 1: Rust 중계와 Hub

**Files:**
- Create: `src-tauri/src/mcp.rs`
- Modify: `src-tauri/src/main.rs`, `src-tauri/src/lib.rs`(`mod mcp;`, `setup`에서 `mcp::setup(app.handle())`, 커맨드 등록)

**Interfaces:**
- Produces (Rust):
  - `pub fn mcp_json_path() -> Option<PathBuf>`
  - `pub struct Hub`, `Hub::start(token: String, on_line: impl Fn(u64, String) + Send + Sync + 'static) -> io::Result<(Arc<Hub>, u16)>`
  - `impl Hub { pub fn set_ready(&self); pub fn respond(&self, conn: u64, line: &str) -> io::Result<()> }`
  - `pub fn relay_io(input: impl BufRead, output: impl Write + Send + 'static, connect: impl FnMut() -> io::Result<TcpStream>, token: &str) -> io::Result<()>`
  - `pub fn relay() -> i32`
  - `pub fn setup(app: &AppHandle)`: 토큰을 만들고 `Hub`를 시작한다. `mcp.json`에 `{"port":u16,"token":String}`을 쓰고 `Hub`를 `manage`한다. `on_line`은 `app.emit("mcp-request", {conn, line})`을 호출한다.
- Produces (Tauri 커맨드): `mcp_ready()`(`hub.set_ready()` 호출), `mcp_respond(conn: u64, line: String)`
- Produces (이벤트): `mcp-request`, payload `{ conn: number; line: string }`

토큰은 새 의존성 없이 `RandomState::new().build_hasher()`로 만든다. 64비트 두 개를 시간·pid와 섞어 32자리 hex로 쓴다. `// ponytail:` 주석으로 "OS 난수 크레이트가 필요해지면 교체"라고 남긴다.

`Hub`의 동작:
- 연결마다 증가하는 id를 매기고, 연결마다 스레드를 하나 둔다.
- 첫 줄이 토큰과 다르면 끊는다.
- 줄 끝 `\r`은 제거하고, 빈 줄은 무시한다.
- `set_ready` 전에 온 줄은 `Vec<(u64, String)>`에 쌓았다가 `set_ready`에서 순서대로 `on_line`으로 보낸다.
- 연결이 끊기면 쓰기 핸들을 맵에서 지운다. 지워진 연결로 `respond`하면 `Err`.

`relay_io`의 동작:
- `connect()` 직후 토큰 줄을 보낸다. 소켓→`output` 복사는 별도 스레드가 맡는다.
- `input`의 각 줄에서 `id`와 `method`가 둘 다 있으면 대기 id 집합에 넣고, 소켓에서 온 줄의 `id`는 집합에서 뺀다.
- 소켓 쓰기가 실패하거나 소켓 읽기가 EOF면 대기 id마다 `{"jsonrpc":"2.0","id":<id>,"error":{"code":-32000,"message":"Drive 앱과 연결이 끊겼습니다. 다시 시도해 주세요."}}`를 `output`에 쓴다. 그다음 줄이 오면 `connect()`를 다시 부른다.
- `input`이 EOF면 대기 id가 모두 응답받을 때까지 최대 5초 기다린 뒤 `Ok(())`를 반환한다(파이프로 한 줄 보내고 stdin을 닫는 클라이언트도 응답을 받게).

`relay`의 `connect`는 `mcp.json`을 읽어 접속한다. 실패하면 `std::env::current_exe()`를 `--autostart`로 한 번 띄우고, 300ms 간격으로 15초간 재시도한다. 끝내 실패하면 stderr에 사유를 쓰고 종료 코드 1로 끝낸다.

`main.rs`는 `std::env::args().any(|a| a == "--mcp")`이면 `std::process::exit(seadrive_lib::mcp::relay())`를 호출하고, 아니면 `run()`을 호출한다.

### Task 5: 도구 (`tools.ts`)

**Files:**
- Create: `src/features/mcp/tools.ts`, `src/features/mcp/tools.test.ts`

**Interfaces:**
- Consumes: `waitSettled`(Task 3), `UploadQueue.add`/`DownloadQueue.add`의 id 반환(Task 3), `IndexedEntry`(`useSearchIndex.ts`), `searchEntries`(`searchIndex.ts`)
- Produces:

```ts
export interface LocalFile { name: string; path: string; size: number; mtime: number }
export interface ToolCtx {
  storage: StorageProvider;
  uploads: UploadQueue;
  downloads: DownloadQueue;
  searchIndex(): { entries: IndexedEntry[]; loading: boolean };
  readLocalFile(path: string): Promise<File>;          // Tauri read_local_file → File(이름 = 경로의 마지막 부분)
  freePath(dir: string, name: string): Promise<string>;
  defaultDownloadDir(): Promise<string>;               // 설정 downloadDir ?? OS 다운로드 폴더
  recentFiles(dir: string, limit: number): Promise<LocalFile[]>;
}
export interface ToolResult { content: { type: "text"; text: string }[]; isError?: boolean }
export const TOOLS: { name: string; description: string; inputSchema: object }[];
export async function callTool(name: string, args: Record<string, unknown>, ctx: ToolCtx): Promise<ToolResult>;
export function normalizeDir(dir: string): string;
export async function resolveTarget(storage: StorageProvider, libId: string, dir: string): Promise<{ targetDir: string; relativePath?: string; existing: Entry[] }>;
```

입력 스키마와 동작은 설계서의 "도구" 표를 그대로 따른다. 결과 `text`는 `JSON.stringify`한 객체다. 그 밖에 정할 것은 다음과 같다.
- `normalizeDir`: 앞에 `/`를 붙이고, 연속 `/`를 하나로 줄이고, 끝 `/`를 뗀다. 빈 문자열은 `/`.
- `resolveTarget`: `listDir(dir)`이 성공하면 `{ targetDir: dir, existing }`. `notFound`면 부모로 올라가며 처음 존재하는 폴더를 `targetDir`로 삼고, 나머지 경로를 `relativePath`로, `existing`은 `[]`로 둔다.
- 업로드 전 검사: 저장소가 없거나 `encrypted`이면 "암호화 저장소에는 올릴 수 없습니다", `readOnly`이면 "읽기 전용 저장소입니다". 받기도 `encrypted`면 거절한다.
- 충돌 결과: `{ uploaded: [], conflicts: string[], message: "같은 이름의 파일이 있습니다. 사용자에게 덮어쓸지 물어본 뒤 overwrite: true로 다시 호출하세요." }`, `isError` 없음.
- 업로드 완료 결과: `{ uploaded: [{ name, path }], failed: [{ name, error }] }`. `waitSettled`의 settled 상태는 `done`·`failed`·`cancelled`.
- `download`: 폴더면 "파일만 받을 수 있습니다" 오류. 저장 폴더는 `local_dir ?? await ctx.defaultDownloadDir()`. 결과는 `{ saved: string[], failed: [{ path, error }] }`. settled 상태는 `done`·`failed`.
- `search`: 결과는 최대 20개이고, 각 항목은 `{ library, libraryName, path, type, size }`. 색인이 `loading`이면 `note: "색인 중이라 결과가 일부일 수 있습니다"`를 붙인다.
- `recent_downloads`: `limit` 기본 10. `ctx.recentFiles(await ctx.defaultDownloadDir(), limit)`.
- `upload_text`: `new File([content], name, { type: "text/plain" })`. UTF-8로 저장된다.
